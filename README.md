# 开工先确认（requirement-check-first）

一个给 AI Agent 用的 Skill。核心规则一句话：**每条工作请求动手前先过一道确认——写不出「我打算这么做」，就先问；写得出来，就写下默认假设直接干。**

## 解决什么问题

- 需求没对齐就动手，做错方向再返工。
- 为了「显得严谨」机械提问、走流程，浪费用户时间。
- 该问的不问，闷头做完才发现不是用户要的。
- 摘要里一句「需求已明确就直接开工」，被模型拿来自我豁免，最终什么都没确认。

## 适用 / 不适用

**触发（属于任务）**：要产出文档 / 表格 / PPT / 代码 / 网页 / 报告、要改文件、要多步连续操作、要访问外部数据或登录态。

**不触发（直接做）**：纯知识问答、概念解释、闲聊、单句级微调（改错别字 / 调颜色 / 换措辞）、需求已完整交代。

## 安装

这是 DeepSeek Harness（DSH）的 Skill，以 `SKILL.md` 文件形式加载。

把本仓库的 `requirement-check-first` 文件夹（含 `SKILL.md`）复制到你的 skill 目录：

- 用户级（推荐）：`~/.agents/skills/`（Windows：`C:\Users\<你>\.agents\skills\`）
- 用户级（备选）：`~/.dsh/skills/`
- 项目级：项目根目录的 `.dsh/skills/` 或 `.agents/skills/`

目录名必须保持 `requirement-check-first`（与 `SKILL.md` frontmatter 里的 `name` 一致）。放好后重启或刷新会话即生效。

## 使用

放进 skill 目录后，DSH 会按 `SKILL.md` frontmatter 里的 `description` 自动判断何时触发；也可以直接点名加载这个 skill。

## 核心规则

1. **任务判定**：先判断是不是任务。不是任务直接做，不走流程。
2. **那句话**：是任务，先写「我打算这么做：第几页／哪一段；原来是什么；改成什么；哪些不做」。写不出来就不许动手，先问。
3. **缺项清单**：产物 / 受众 / 范围 / 硬约束 / 验收五项，没交代的逐条列出并给默认值。一项不缺也明写「五维齐」。
4. **提问**：不确定就问，题数不设上限，一次问完，每题给出我认为的答案。他答不全或没回，按默认值开工并写明「按默认做的」。
5. **大任务先拆**：说清分几步、每步产出什么、动哪些工具，一次问要不要分开做。
6. **工具成本**：只读文件不问；会改文件或启动外部程序的，在开工确认里一次说清，点头后中途不再问。
7. **做不到先说**：到不了目标水平就说降级做或不做了，不硬交一版。
8. **返工报死因**：指出那句话在哪一点写错了，并把新口径补进长期记忆。

完整规则见 `SKILL.md`。

## 改动记录

- **2026-11-18 重写**：v1 的「需求已明确就直接开工」被指出会被 AI 拿来自我豁免，改成「写不出那句话就不许动手」；提问方式从「1–4 题、每题 2–4 选项」改成「不设上限、一次问完、每题给默认答案」，因为选项堆跟用户「给判断、不给选项堆」的风格直接冲突；显示名改为「开工先确认」。
